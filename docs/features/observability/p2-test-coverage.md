## Historical API and fixture feedback to integration owner (mid-implementation; resolved unless listed above)

The exported `traceAIInvocation()` wrapper provides a fake async operation and parse-outcome hook; its focused parentage, exact-token, abort and privacy tests pass. It currently wraps the whole chain, including prompt formatting, while the factory client itself is uninstrumented. A fake `ChatOpenAI.prototype.invoke` through `getLLMClient()` yields no AI span or usage metric. This prevents the provider-attempt signal from meaning an actual model call, and a prompt failure can be counted as a provider failure. The source owner should put attempt telemetry at the client invocation boundary and keep application parse/schema outcome separate. Expose cost calculation/report functions on explicit synthetic records so tests can cross dated rates without calling providers or importing live policy. Keep the official SDK exporter available through `createTestTelemetry()` for privacy and sampling assertions.

Initial RED run of a direct `parseResume` fixture found a pre-existing `PromptTemplate` failure before `model.invoke`: literal `{ state, zip }` in the prompt is treated as an input variable. The same literal JSON-brace pattern appears in other chat prompts. This is a source-path blocker to proving actual invocation through those chains; the tester does not own production source and will target the instrumented invocation seam while the integration owner triages it. The RED store/workflow tests independently show absent P2 spans on baseline `85ae966`. Initial test command was `node --import tsx --test tests/observability-p2-store-workflow.test.ts` after `npm ci --ignore-scripts --no-audit --no-fund`; 3/3 expected RED on missing instrumentation. Environment: macOS, Node v24.20.0, local synthetic temp store; no reviewer yet.

Cost counterexample on the in-progress `src/telemetry/cost.ts`: a record at `2026-10-01T00:00:00Z` with 1,000,000 input tokens uses the v2 rate (2,000 micro-USD), but `applyCost()` reports `priceVersion: synthetic-v1`. The catalog lookup for the label selects the first matching model rather than the effective catalog. `tests/observability-p2-cost.test.ts` records this RED; the cost source owner must correct it. The report interface currently lacks environment/release filters and an explicit completed logical outcome or operation ID, so S06-AC3 cannot be accepted from `attempt === 1` alone. Reused vectors represented as a zero-token `UsageRecord` would also inflate its completed-operation denominator; reuse should be represented as no billed provider attempt.

Usage counterexample on the in-progress `src/telemetry/usage.ts`: Anthropic reports `input_tokens` separately from `cache_read_input_tokens` and `cache_creation_input_tokens` ([Anthropic pricing and usage semantics](https://docs.anthropic.com/en/docs/about-claude/pricing)).
